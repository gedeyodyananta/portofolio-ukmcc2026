Overview

Project Overview

This project is a responsive E-Commerce Website developed as a university Web Programming course project at Politeknik Negeri Bali. My responsibility focused on frontend implementation, creating a clean, responsive, and user-friendly shopping experience.

The goal was to build a complete online store covering product browsing, cart management, and user authentication — all within a cohesive and accessible UI built with PHP, JavaScript, CSS, and MySQL.

Problem

The Challenge

Building a shopping experience that feels coherent — without a modern framework — requires solving four problems simultaneously.

01

Designing a responsive layout

Creating a UI that works on mobile, tablet, and desktop without a utility framework — only hand-written CSS flexbox and media queries.

02

Organizing product information

Displaying products, categories, and details clearly so users can browse and decide without friction — all from raw MySQL query data.

03

Building reusable frontend components

Six pages needed to look consistent. Without a component library, every reusable element had to be extracted into PHP include partials manually.

04

Creating intuitive navigation

Cart state, authentication, and page routing all needed to flow naturally — managed through PHP sessions and deliberate JavaScript DOM updates.

Solution

How It Was Solved

The solution was built around four principles: a clear data layer, reusable partials, a manual CSS variable system, and a strict JS boundary.

Responsive UI was achieved with a custom CSS file that defines spacing, color, and font variables once — all six pages share the same tokens. Breakpoints were set for three viewport sizes using standard flexbox and grid.

Component organization was handled through PHP includes: a single header.php, footer.php, and product-card.php are shared across every view. A change to any one partial applies site-wide.

User-friendly layout followed an information hierarchy approach — product image large at the top, title and price prominent, description and specs below, CTA always visible.

Clean code was maintained by keeping PHP controllers thin: they only fetch data and pass it to templates. All business logic stays in dedicated function files, not embedded in views.

Technology

Stack & Rationale

Each technology was chosen deliberately — not just because it was available.

Backend

PHP

Handles server-side routing, session management, and HTML rendering. PHP includes enabled a reusable partial system without any build step.

Interactivity

JavaScript

Handles only UI behavior — cart quantity updates, image switching, form validation. No page reload for these interactions, keeping the experience fluid.

Styling

CSS3

Hand-written with a CSS custom property system for the full design token set. Writing it without a framework built a deep understanding of the cascade.

Database

MySQL

Five normalized tables for users, products, categories, cart items, and orders. Writing raw SQL for every query built a solid understanding of relational data.

Process

Development Process

Five sequential phases, each building directly on the previous.

  1. Phase 01

    Planning

    Defined all pages, user flows, and the five-table database schema on paper before opening an editor. Mapped the full cart and authentication lifecycle.

  2. Phase 02

    Wireframe

    Created Figma wireframes for the homepage, product detail, and cart. Set up the CSS variable system before writing a single styled component.

  3. Phase 03

    Frontend Development

    Built database, PHP routing, and SQL queries first. Then applied the CSS design system page-by-page. JavaScript interactivity was the final layer — added only after the HTML/PHP structure was solid.

  4. Phase 04

    Testing

    Tested every user flow manually: empty cart, invalid credentials, out-of-stock products, long text in product names. Verified all three breakpoints on real device sizes.

  5. Phase 05

    Refinement

    Fixed layout inconsistencies found during testing, polished empty states for zero-result searches and empty cart, and cleaned up the codebase before final submission.

Reflection

Lessons Learned

01

Responsive frontend development

Through this project, I improved my understanding of building layouts that adapt gracefully across devices using flexbox, grid, and media queries — all without a framework.

02

UI consistency

Learned the importance of establishing a design system early. Using CSS variables for spacing, color, and typography ensured visual consistency across all six pages.

03

Component organization

Breaking down the UI into reusable PHP partials made maintenance easier. A single change to the header component updated it everywhere instantly.

04

Building user-friendly web interfaces

Focused on intuitive navigation patterns, clear visual hierarchy, and smooth interactions using PHP, JavaScript, CSS, and MySQL to create a cohesive shopping experience.
